# Real-ESRGAN 精度评估

本轮仅评估模型，不接入产品档位、替换安装包资源或改变默认后端。结论：**半精度有加速收益，但当前 DirectML 组合下更占显存，不能直接定义为“轻量档”。**

## 环境与方法

- 代码基线：`0f6ac91856978194375bb698d7f7496469f8f904`；原模型和测试输入在测量前后 SHA-256 一致。
- Ryzen 7 9700X，8 核 / 16 线程，64 GB；Windows 11 Enterprise 10.0.26200。
- RTX 5060 Ti，8151 MiB 显存，驱动 610.88；独立后台进程，不启动应用或占用前台。
- 主测使用 Release UI 实际原生 ORT **1.23.2**、DirectML **1.15.4**；另用 ML.Test 的原生 ORT **1.20.0** / DirectML **1.15.2** 做小尺寸兼容性检查。托管 ORT 都为 1.20.0，不能根据该程序集版本推断原生版本。
- 原图为 opset 14、702 个 float 权重；转换图对应权重为 float16，保留 float 输入输出接口，阻止转换的算子沿用转换器默认列表。转换器及复现方式见 [README](README.md)。
- 两种输入：确定性的梯度/边缘合成图、现有 `resources/readme/upscale-input-960.jpg` 的中心裁剪，各为 RGB NCHW 512×512。两轮新进程 A/B、B/A，各首次运行后记录 3 次热运行，每种图/输入有 6 个有效热样本。
- 内存为单探针进程导出前的工作集，以及每 100 ms 采集的 GPU 专用/共享使用量。并非全卡或整个应用内存。执行轨迹另跑，不混入计时。

## 实测结果

| 项目 | FP32 原图 | FP16 转换图 |
| --- | ---: | ---: |
| 模型文件，十进制 MB | 67.05 | 33.76 |
| 合成图热运行中位数 | 708.86 ms | 509.41 ms |
| 合成图热运行范围，6 次 | 703.74–710.19 ms | 500.33–520.84 ms |
| 照片热运行中位数 | 709.20 ms | 506.95 ms |
| 照片热运行范围，6 次 | 708.05–711.85 ms | 503.53–517.01 ms |
| GPU 专用使用量峰值，两轮 | 3.23 GiB | 4.91 GiB |
| GPU 共享使用量峰值 | 99.10 MiB | 99.72 MiB |
| 合成图进程工作集峰值 | 428.87 MiB | 445.63 MiB |
| 照片进程工作集峰值 | 409.16 MiB | 428.53 MiB |

半精度模型文件缩小 **49.65%**，两组输入的热运行耗时分别下降 **28.14% / 28.52%**，但专用显存峰值提高约 **52.0%**。两轮及单独 profiling 都复现了更高显存占用。仅凭这些数据不能确定具体内部分配原因，不能把文件大小减半等同于显存减半。

正式对照中的会话创建约 393–448 ms，首次运行约 956–1131 ms，半精度没有一致的首次运行优势。更早的小尺寸兼容性检查曾出现原图首次运行约 18.9 s、半精度会话创建约 51.0 s；驱动和文件缓存没有清空，因此这些初次检查不是受控的冷启动比较。需要保留首次加载进度反馈，不能承诺首次就获得热运行加速比。

GPU 执行轨迹中两种图带 provider 的计算记录均为 DirectML，转换图卷积的输入/输出确认为 float16；不是未发现的整图 CPU 回退。

## 数值与 CPU 回退

| 相对同输入 FP32 GPU 输出 | 合成图 | 照片 |
| --- | ---: | ---: |
| 平均绝对误差，原始 float | 0.000912 | 0.000877 |
| 最大绝对误差，原始 float | 0.05859 | 0.06247 |
| PSNR，以名义范围 1 计算 | 56.35 dB | 57.73 dB |
| 按产品方式转 RGB8 的平均通道误差 | 0.183 / 255 | 0.224 / 255 |
| RGB8 最大通道误差 | 15 / 255 | 16 / 255 |
| RGB8 通道误差超过 2 的比例 | 0.287% | 0.107% |

所有测量输出尺寸正确且无 NaN/Infinity；同精度、同输入两轮输出完全一致。平均差异较小，局部仍有偏差；没有真实高分辨率标注，也未做主观质量验收，不能据此宣称更高画质或无损。

原生 ORT 1.20.0 / 1.23.2 都能执行 32×32 半精度图的 GPU 和 CPU 路径。主测 1.23.2 还完成了两种精度的 512×512 CPU 推理：FP32 热中位数约 **18.98 s**，FP16 约 **18.66 s**，工作集均约 **2.15 GiB**。CPU 单独一进程、3 个热样本不足以证明小幅性能差异；profile 显示半精度图的主要卷积被转换成 float CPU 运算，并非原生半精度 CPU 加速。

这验证了本机的半精度图 CPU 可执行性，没有模拟 GPU 中途掉线或运行产品的整次任务重试。落地时仍推荐保留 FP32 作为 CPU 基准资源，避免把其他 CPU/驱动/版本上的 float16 兼容性当作既定条件。

## 对产品方案的影响

后续决定取消处理档位，沿用现有 FP32 模型，以任务中的「使用 GPU」选项选择设备：

1. **关闭硬件加速**：保持 CPU 流程，不显示 GPU 选项。
2. **超分与高清处理**：默认勾选 GPU，并说明处理时间与显存占用的取舍；风格迁移自身继续使用 CPU。
3. **深度图**：不新增 GPU 选项，沿用既有界面、模型设备策略及缓存流程。
4. **任务隔离与回退**：提交后固定选择，同设备复用、切换前等待已有任务结束；GPU 故障继续整次 CPU 重试一次。

这轮模型评测只新增手动工具和文档，未加入测试门禁、真实 UI 或安装验收。转换图留作实验，不进入产品包；GPU 选择的后续实现见[架构说明](../../doc/architecture.md)。
