# README artwork and motion previews

- `hero.svg` combines the product name, official transparent application icon from `src/VirtualPaper.UI/Assets/icon-vp-512.png`, and the two real library captures on one continuous background. Pale violet behind the branding blends into dusk blue behind the dark window, with a soft aqua highlight below. The larger light window sits in front of the dark window. Transparency applies to the background; both screenshots stay opaque and readable. All images are embedded, with no external font, image, or script dependencies. The background and layout are original vector artwork, as are `download.svg` and `scene.svg`.
- `snow.gif`, `fireflies.gif`, `meteors.gif`, and `petals.gif` render the production drawing routines in `src/VirtualPaper.PlayerWeb.Core/PLAYER_Web/js/effects/` over `scene.svg`. They are effect demonstrations, not recordings of the application UI or AI-generated image animation.
- Each atmosphere GIF is 480×270, with 64 frames at 80 ms per frame (5.12 seconds, 12.5 fps), repeating for easy viewing. The preview loop does not imply seamless looping of generated videos.
- `parallax.gif` compares the unmodified production regular player (`default.html` / `js/default/run.js`, left) with the depth player (`3d_depth_map.html` / `js/3d_depth/run.js`, right), using Emerald hills and the same repeating five-second mouse trajectory. Both players render at a real desktop viewport of 1920×1080 before being reduced for the comparison; rendering the regular player directly at thumbnail size would weaken its CSS perspective. Regular parallax retains its 1.05 scale and 2-degree tilt. Depth parallax uses Standard strength (1, shader value 0.024), with automatic drift off. The pointers indicate the supplied mouse position. This is a player demonstration, not a recording of the application window.
- The parallax GIF is 812×253 with a five-second loop, sampled at up to 10 fps. Native RAF, depth smoothing, and CSS transitions run in real time. Browser frames use JPEG quality 95 and a shared 256-color GIF palette. Frame durations follow the actual capture intervals, rather than speeding up slower captures. The final frame is an exact copy of the first, whose duration is split between both ends to avoid adding a pause. Neither player parameters nor shaders are modified for this preview.
- `parallax-source.jpg` is the same 1920×1080 Emerald hills photograph used in the library. `parallax-depth.png` was generated from it by the production `DepthAnythingV2.LoadModel` / `Run` / `SaveDepthMap` methods using `depth_anything_v2_vits_dynamic.onnx`, default 518-pixel FitLongestSide preprocessing, and CPU FP32 inference. These two inputs are kept here so the GIF can be regenerated without downloading an image or running inference again. No hand-painted depth map, additional image warping, or AI video generation is used.
- `library-light-mica.jpg` and `library-dark-mica.jpg` are real 1446×893 captures of the current local Release application, taken on November 4, 2026. Both use the English interface, Mica, and the same isolated demonstration library. The JPEG files preserve the capture tool's original bytes. No application controls, text, or thumbnails were redrawn.
- `editor-light-mica.jpg` is a real 1446×893 capture of the English image editor in Light mode with Mica, taken on November 4, 2026. The original blue mountain and lake scene was drawn in the application using its brush and fill tools. It uses no stock photograph or imported background image. The JPEG preserves the capture tool's original bytes; neither the drawing nor the application controls were altered after capture.
- Only the library captures' scale, placement, surrounding background, and shadows are composed. Run `python resources/readme/compose-showcase.py` to rebuild `hero.svg` from the two library JPEGs and official icon.
- The style transfer comparison uses the bundled `demo/style_transfer/origin.jpg`, the actual `preset_styles/watercolor.jpg` reference, and `style-watercolor-result.jpg`. The result is generated by the production `AdaIn.LoadModel` / `RunAndSave` methods with `adain_style_transfer.onnx`, alpha 1.0, and a 512-pixel short edge for both inputs. It replaces the older result whose reference was not recorded. No post-processing is added.
- `upscale-input-960.jpg` is the Ocean breeze photograph downsampled from 1920×1080 to 960×540 with OpenCV `INTER_AREA`, then saved at JPEG quality 95. `upscale-result-4k.jpg` is generated from that exact input by the production `Realesrgan.LoadModel` / `RunAndSave` methods and bundled `realesrgan_x4plus_dynamic.onnx` model, using the normal CPU implementation, 512-pixel tiles, 16-pixel overlap, and 3840×2160 output at JPEG quality 95. This is a downsampling example, not a claim to recover the original photographic detail exactly.
- `upscale-detail-bicubic.png` and `upscale-detail-model.png` are matching 720×480 crops at output coordinates (2100, 1180). The baseline enlarges the same decoded 960×540 input to 3840×2160 with OpenCV `INTER_CUBIC`, saved at the same JPEG quality 95 before cropping. Both crops use the same display width, with no added blur or sharpening. The full 4K model result is linked from the main README.

## Regenerate the GIFs

Use Python 3.10 or later with `Pillow` and `websocket-client`, plus Chrome or Edge installed on Windows:

```powershell
python resources/readme/generate-previews.py
# Optional browser override:
python resources/readme/generate-previews.py --browser "C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe"
# Depth parallax comparison, using the saved source image and depth map:
python resources/readme/generate-parallax-preview.py
```

The script uses a private headless browser profile and a loopback-only HTTP server. It does not access the user's browser profile or launch VirtualPaper. The seed, intensity, dimensions, and timestep are fixed for repeatable previews. A shared GIF palette avoids frame-to-frame color changes in the static background.

The scripts only write GIFs here. Temporary browser profiles, contact sheets, and parallax render checks are saved under the ignored `TestResults/readme-refresh-20261104/` directory. Run the relevant script again when the production effects or depth player change, then check both the animation and file sizes.
